01

方案总览：不是文件网盘，而是 Artifact 发布平台

定义产品边界、核心对象与第一期必须兑现的安全不变量。

Asset

Artifact

一个长期存在的可视化作品，有稳定 ID、Slug、Owner、Workspace、访问策略和发布地址。

Release

Immutable Version

每次上传形成独立版本。发布不覆盖旧文件，回滚只改变当前版本指针。

Governance

Workspace + ACL

资源归属与创建者分离；通过部门、项目成员关系和单资源授权管理访问。

范围边界：第一期只托管静态 HTML / CSS / JS / 图片 / 字体 / JSON。绝不把 ZIP 中的 Python、Node、PHP、CGI 当成可运行服务。动态应用必须进入独立的受限运行时，不能复用静态文件网关。

产品对象关系

必须守住的七条不变量

  1. Default deny；每个 API 和静态资源请求都必须授权。
  2. 管理域与用户内容域分离；每个 Artifact 使用独立 Host / Origin。
  3. Quarantine 与 Published 分开；未验证内容绝不进入正式发布空间。
  4. MinIO Bucket 私有；浏览器不能拿到长期对象读取凭证。
  5. 对象键由服务端生成；用户文件名不能决定存储路径。
  6. 版本不可变；发布失败不能影响线上当前版本。
  7. 发布、撤权、回滚、Owner 转移和拒绝访问都必须审计。
02

总体架构：三个平面，四个核心进程

控制平面管理身份与元数据；发布流水线处理不可信输入；交付平面执行逐请求授权。

Go API

控制平面：身份上下文、Workspace、Artifact、ACL、配额、上传会话、任务入队和审计。保持模块化单体，不急于微服务化。

Upload Worker

无公网入口。只拥有隔离区读取和正式区创建版本的权限。执行 ZIP 验证、恶意扫描、Manifest 生成与发布。

Static Gateway

独立进程、只读正式 Bucket。按 Host 解析 Artifact；每个 HTML 和子资源请求都校验用户、状态和 ACL。

PostgreSQL + MinIO

PostgreSQL 保存关系和状态；MinIO 保存对象。不要把二者想象成一个跨系统 ACID 事务。

工程取舍：先部署 API、Worker、Gateway 三个进程，不采用 Kafka、Kubernetes 或服务网格作为 MVP 前置条件。后台任务使用 PostgreSQL Job 表 + SKIP LOCKED + Lease + Outbox，验证真实吞吐后再引入独立队列。

关键规则：created_by 只表示最初创建者，不代表永久拥有者。资源 Owner 可以是部门、项目或公司。员工离职不能导致项目资产失去 Owner。

授权决策顺序

  1. 验证用户身份 active、会话有效；无效直接拒绝。
  2. 解析资源真实 ID；不能从客户端传来的 workspace_id 推断资源归属。
  3. 加载 Artifact 状态、Workspace 归属和成员关系。
  4. Owner / Workspace Role 提供基础权限。
  5. 检查直接用户或用户组 ACL，并校验 expires_at。
  6. 没有明确 Allow 时拒绝；所有决策记录 reason code。
Authorization pseudocode 
func Can(user, artifact, action):
    if !user.active: return DENY("user_inactive")
    if artifact.status != "PUBLISHED" && action == READ:
        return DENY("artifact_unavailable")

    role = resolveWorkspaceRole(user.id, artifact.workspace_id)
    if role.allows(action): return ALLOW("workspace_role")

    grants = activeArtifactACL(user, artifact.id, now())
    if anyGrantAllows(grants, action): return ALLOW("artifact_acl")

    return DENY("no_matching_grant")

组织同步与生命周期

  • 使用企业 IdP 的稳定 subject / employee ID，不以邮箱作为主键。
  • 部门组织关系同步和项目成员关系分开管理；调岗不自动清除项目成员。
  • 离职流程：禁用用户 → 撤销会话 → 冻结个人资源 → Owner 移交 → 保留审计。
  • Owner 转移必须记录原 Owner、新 Owner、操作者、审批号和时间。
  • PostgreSQL RLS 作为纵深防御；应用数据库角色不能是表 Owner 或 BYPASSRLS。
04

身份与 Origin：把用户上传脚本隔离在自己的浏览器边界

这是整个系统最重要的安全设计之一。

不要把内容放在管理平台同源路径下。上传 HTML 可以执行 JavaScript。不同路径不构成安全边界；不同子域名是不同 Origin，但 Cookie Domain 可能仍覆盖父域。推荐管理域和内容域使用不同的可注册域名（eTLD+1）。

Management Origin

https://visual.company.example

管理 Portal、API、Workspace、用户会话和权限操作。Host-only Cookie。

Content Origin

https://<artifact-id>.visual-content.example.net

每个 Artifact 独立 Host。其脚本不能读取管理域 DOM、Web Storage 或 Host-only Cookie。

跨域 SSO：一次性 Ticket Exchange

1 · 浏览器访问 Artifact Host
2 · Gateway发现无会话
3 · OIDC Brokerstate / nonce / PKCE
4 · 企业 IdP完成认证
5 · Ticket30 秒、单次、绑定资源
6 · CookieHost-only Session

Ticket 绑定 user_id + artifact_id + canonical_host + expires_at + single_use，数据库只存 Ticket hash。Gateway 通过服务端 back-channel 兑换，不信任浏览器传入的 user_id。兑换后 303 跳回原始路径，清除 query string。

Host-only Cookie 
Set-Cookie: __Host-vh_session=<opaque-random-session>;
  Secure; HttpOnly; SameSite=Lax; Path=/

# Never set Domain=.visual-content.example.net
# Never place management bearer tokens in localStorage or URLs
  • OIDC Authorization Code Flow + PKCE S256；校验 issuer、audience、signature、exp、nonce、state 和 redirect URI。
  • Ticket TTL 建议 30 秒；一次性消费；记录 ticket_id，不记录票据原文。
  • Session Cookie 使用 Secure、HttpOnly、SameSite=Lax、Path=/、无 Domain，并采用 __Host- 前缀。
  • return_to 只能是服务端登记的 Artifact Host 和合法路径，禁止开放重定向。

06

ZIP 安全：路径、资源与内容都要验证

ZIP Slip、符号链接、压缩炸弹和重复路径是发布链路的 P0 攻击面。

路径安全

  • 拒绝绝对路径、盘符、反斜杠、NUL。
  • 拒绝 .、.. 越界段和双重编码路径。
  • 规范化 Unicode、大小写后检查冲突。
  • 拒绝重复条目名和文件/目录命名冲突。

资源安全

  • 累计实际解压字节数。
  • 限制文件数、单文件大小、目录深度。
  • 限制压缩比、CPU、内存、磁盘和运行时长。
  • MVP 不递归展开嵌套压缩包。

文件类型

  • 拒绝 symlink、device、FIFO、socket。
  • MIME 由服务端根据扩展名与内容检测生成。
  • 不执行 PHP、CGI 或任何服务端扩展名。
  • 默认要求 ZIP 根目录存在 index.html。

处理环境

  • 独立非 root Worker UID。
  • 临时目录和磁盘配额；无宿主机敏感挂载。
  • 默认无外网和内网访问。
  • 完成后清理临时目录并记录审计。
Go archive path guard · 示意代码 
func safeArchivePath(root, entry string) (string, error) {
    if strings.Contains(entry, "\\\\") || strings.ContainsRune(entry, 0) {
        return "", ErrInvalidPath
    }
    if strings.HasPrefix(entry, "/") || hasDrivePrefix(entry) {
        return "", ErrAbsolutePath
    }

    clean := path.Clean(entry)
    if clean == "." || clean == ".." || strings.HasPrefix(clean, "../") {
        return "", ErrPathTraversal
    }

    dst := filepath.Join(root, filepath.FromSlash(clean))
    rel, err := filepath.Rel(root, dst)
    if err != nil || rel == ".." ||
       strings.HasPrefix(rel, ".."+string(os.PathSeparator)) {
        return "", ErrPathTraversal
    }
    return dst, nil
}

此代码仅展示路径边界。生产实现还需读取 FileHeader.Mode() 拒绝符号链接与特殊文件，使用安全创建文件语义，避免目标路径被并发替换，并对规范化后的路径做唯一性检查。Go 标准库 archive/zip 提供 ErrInsecurePath，但不能替代应用层资源预算和路径策略。

07

版本与发布：不可变对象 + 原子指针

PostgreSQL 与 MinIO 没有共同事务；必须显式设计跨系统失败恢复。

Object key layout 
quarantine/{upload_id}/source.zip

published/{workspace_id}/{artifact_id}/
  versions/{version_id}/
    index.html
    assets/app.js
    assets/site.css
    images/chart.svg
    manifest.json

发布事务

  1. 创建 Version，状态设为 STAGING，生成全新 version_id。
  2. Worker 将每个文件写入新的不可变对象前缀；不覆盖历史对象。
  3. 计算并校验每个对象 SHA-256、总字节数、文件数和 Manifest hash。
  4. Manifest 最后写入；验证所有对象 HEAD / checksum。
  5. 开启 PostgreSQL 事务：Version → READY，Artifact.current_version_id → 新版本，写 Audit + Outbox。
  6. 事务提交后，Gateway 的稳定 URL 才指向新版本。
关键失败语义：对象上传成功但 DB 事务失败时，线上仍指向旧版本；新前缀标记为孤儿对象，进入延迟清理队列。绝不能先切 DB 指针再上传对象。

回滚与删除

  • 回滚只允许指向状态为 READY 的历史版本；只更新 current_version_id。
  • 固定版本 URL 仍必须经过 Artifact ACL；版本 ID 不等于访问凭证。
  • Artifact 先软删除和撤销访问；经过 retention period 后再清理对象。
  • 应用级版本前缀与 MinIO Bucket Versioning 是两层保护；非当前对象版本必须配置生命周期策略。

10

Static Gateway：每个资源请求都是一次授权边界

HTML 页面、JS、CSS、图片、字体、JSON 等子资源都必须经过同一条受控路径。

GET /assets/app.js · request pipeline 
1. Validate Host against trusted host allowlist
2. Resolve canonical host -> artifact_id (DB mapping)
3. Load host-only session -> user_id
4. Validate user active + artifact published
5. Authorize(user_id, artifact_id, "read")
6. Normalize URL path exactly once; reject traversal / NUL / backslash
7. Resolve path via version Manifest (not raw object-key concatenation)
8. Fetch object from private Published Bucket
9. Set MIME, CSP, nosniff, Referrer-Policy, cache headers
10. Stream response; emit audit / metrics as configured

缓存策略

  • 敏感内容默认 Cache-Control: private, no-store；先保证撤权语义。
  • 如要缓存，缓存键必须包含 Artifact ID + Version ID + normalized path；授权必须先于缓存响应。
  • 不要把跨租户响应放入共享公共缓存；撤权时要有缓存失效策略。
  • ETag / If-None-Match 的 304 响应同样必须先完成授权。

安全响应头

Header策略
X-Content-Type-Optionsnosniff
Referrer-Policyno-referrer
Permissions-Policy默认禁用 camera / microphone / geolocation
Content-Security-Policy先 Report-Only；按静态内容 profile 逐步 enforce
frame-ancestors默认 none；嵌入需明确白名单
Cache-Control默认 private, no-store

对静态 HTML，优先用脚本 hash 构造 strict CSP；生成式 HTML 常有内联脚本，需先 Report-Only 盘点兼容性。CSP 不是 HTML 净化器；独立 Origin 才是主要浏览器隔离边界。

动态运行时：必须作为第二个产品能力独立建设

Streamlit、Dash、Gradio、Jupyter、Python API 与用户自定义服务都不是静态文件。

测试与验收：安全行为必须自动化

建立 Unit → Integration → Security → Browser E2E → Load → Recovery 的测试金字塔。

层级重点验收证据
Unit权限、状态机、路径、Host、Slug边界和默认拒绝单测
IntegrationPostgreSQL / MinIO / Worker对象写入失败、重试、指针切换失败
SecurityZIP Slip / symlink / bomb / XSS / Cookie恶意样本测试集与扫描报告
Browser E2ESSO、上传、发布、撤权、回滚真实浏览器跨 Origin 验证
Load并发上传和静态资源访问p50 / p95 / p99 与资源指标
RecoveryDB / MinIO 故障恢复PITR、任务重放、Manifest 校验

必须通过的 E2E 场景

  1. A 用户不能访问 B 用户的 Personal Artifact，即使知道完整 URL。
  2. 跨部门项目 Viewer 可以看不能发；Editor 可以发不能改 ACL。
  3. 撤销 ACL 后，新请求立即被拒绝；敏感内容不从共享缓存继续返回。
  4. 恶意 ZIP 的 traversal、symlink、压缩炸弹、重复路径均被拒绝。
  5. 扫描失败时正式 URL 不可访问，当前线上版本不受影响。
  6. 发布过程中断时 current_version_id 保持旧版本。
  7. 回滚只切换 DB 指针，历史对象和 Manifest 不变。
  8. MinIO Bucket 直接匿名访问失败；Gateway 无法读取其他 Bucket。
  9. 恶意 Artifact 不能读取管理平台 Cookie、DOM 或 Web Storage。
  10. Worker 重启后未完成任务可恢复；重复消费不会生成重复版本。

性能目标不要先拍脑袋定 QPS。使用 1 个 HTML + 10–50 个静态资源的真实报告包，按并发 10 / 50 / 100 逐级压测，记录授权 P95、对象存储首字节、吞吐、CPU、内存和出口带宽，再确定 SLO。

OpenCode Web 集成：原生发布入口，不做外部套壳

将 Visual Platform 作为 OpenCode Web 内的一项发布能力，而不是另起一个开发工作台。

用户体验

  1. 在 OpenCode Web 当前工作区选择 HTML / ZIP。
  2. 点击 Publish to Visual Platform。
  3. 选择 Personal / Department / Project Workspace。
  4. 系统显示校验、扫描和发布进度。
  5. 完成后回写 Artifact URL、版本号和权限摘要。

集成边界

  • OpenCode Web 是客户端入口，不是对象存储和权限真相源。
  • 所有写操作通过 Visual Platform API。
  • 上传凭证短时、限对象、限 Workspace。
  • 发布成功返回 artifact_id / version_id / url。
  • 授权、审计、回滚由平台负责。

关键架构决策 ADR

这些决策应在研发启动评审时确认，避免实现中途反复改边界。

ADR决策推荐答案代价 / 影响
001内容 Origin 粒度每 Artifact 独立 Host域名与证书管理复杂度增加
002管理 / 内容域不同可注册域名需要额外域名与 SSO Broker
003静态访问授权Go Gateway 每请求授权引入 Gateway 延迟和流量成本
004任务队列PostgreSQL SKIP LOCKED + Outbox吞吐受 DB 约束；后续可换队列
005权限模型Workspace RBAC + Artifact ACL需要统一策略决策和审计
006版本发布不可变前缀 + DB 指针切换需要孤儿对象清理与生命周期
007匿名分享MVP 禁止后续单独设计可撤销 Token
008动态应用独立 Runtime Controller不在静态托管 MVP 范围
最终架构一句话：Go API 管理资源和授权；Worker 在隔离环境处理不可信上传；PostgreSQL 管理归属、状态和版本指针；MinIO 只存私有不可变对象；Go Static Gateway 在独立 Artifact Origin 上逐请求授权并交付静态文件。
